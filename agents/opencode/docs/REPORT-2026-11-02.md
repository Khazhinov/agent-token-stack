# OpenCode migration findings, 2026-11-02

Generic results from setting up the OpenCode part of the stack. Machine values, project names and
host paths stay in `local/`.

## CBM per project

OpenCode 1.19.5 reads a project configuration from `opencode.json` or `opencode.jsonc` at the
project root. It searches the current directory and goes up to the nearest Git directory. The
project configuration overrides the global `~/.config/opencode/opencode.json`.

CBM is attached per project, not globally. A global registration loads about 14 tool schemas into
every session, including folders without code. The project fragment is:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "codebase-memory-mcp": {
      "type": "local",
      "command": ["codebase-memory-mcp"],
      "enabled": true
    }
  }
}
```

If the project already has `opencode.json`, add only the top-level `mcp` object. The `.mcp.json`
format used by Claude Code does not apply to OpenCode. MCP servers are read at session start, so
restart OpenCode after adding the file.

## Plugin strategy

Caveman and Ponytail are stored in the repository and linked into `~/.config/opencode` by
`install.sh`. This keeps the configuration reproducible and works offline.

The vendor Caveman installer is not used: it copies files, appends a block to `AGENTS.md` and may
add `mcp.caveman-shrink`, leaving the managed set. The npm installation path for Ponytail is not
used for the same reason; the local repository path is used instead.

OpenCode converts relative plugin paths to `file://` and loads both plugins. Removing a plugin line
from the `plugin` array and restarting stops loading the plugin completely.

## Duplicate rules

Caveman and Ponytail inject their rules into the system request on every turn. At `full` level the
Caveman ruleset is about 762 words and the Ponytail ruleset about 494 words. A second copy of the
same rules in `AGENTS.md` would duplicate them on every turn and waste context, so `AGENTS.md` keeps
only a short switch section and the plugins remain the single source.

Document formatting rules stay in `AGENTS.md`. They do not duplicate Caveman: Caveman controls chat
answer style, while documents keep normal formal prose.

## Switching

No file edit or restart is needed to change a level:

| Plugin | Off | On | Other level |
|---|---|---|---|
| Caveman | `/caveman off`, `stop caveman`, `normal mode` | `/caveman` | `/caveman lite/full/ultra` |
| Ponytail | `/ponytail off`, `stop ponytail`, `normal mode` | `/ponytail` | `/ponytail lite/full/ultra` |

The default level is `full`. Caveman resets to the default level at the start of each session, so
`/caveman off` lasts until the end of the session. Persist it with `CAVEMAN_DEFAULT_MODE=off` or
`~/.config/caveman/config.json`. Ponytail stores `/ponytail off` in
`~/.config/opencode/.ponytail-active`; `PONYTAIL_DEFAULT_MODE=off` applies only while the state file
does not exist.

Documents mode for a whole run:

```bash
CAVEMAN_DEFAULT_MODE=off PONYTAIL_DEFAULT_MODE=off opencode
```

## Checks that proved useful

- `opencode debug info` lists loaded plugins.
- `opencode debug config` shows the resolved `plugin` array and the imported instruction files.
- `opencode mcp list` from a project root shows whether CBM is attached.
- A Node import check confirms both plugin modules load and their rulesets can be read without
  calling a model.
- A short `opencode run` prompt in `full` mode returns compressed text; the same prompt with both
  modes off returns full sentences.

## Limitations

1. The plugins are vendored; automatic updates are not configured. Update by replacing the files
   from upstream, running `install.sh` again and restarting the session.
2. The Caveman plugin `package.json` reports 0.1.0 while the upstream release is 2.7.0. Both values
   should be named in documentation.
3. Caveman `off` does not persist between sessions without the environment variable or the config
   file.
4. Shared `AGENTS.md` rules ask for compact answers even when Caveman and Ponytail are off.
   Documents mode gives full sentences, but general brevity remains.
