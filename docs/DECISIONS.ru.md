# Решения

[English](DECISIONS.md) | Русский

| # | Решение | Обоснование | Отклонённая альтернатива |
|---|---|---|---|
| S1 | Одна копия каждого общего бинарника (RTK, CBM) на машину, один кэш индексов, один обновляющий процесс за раз; pin CBM и RTK с SHA-256 хранится в одном месте (`BINARY_SPECS` файла `manage.py`) | две копии расходятся; параллельные обновление и индексация повреждают общий кэш | каждый агент ставит свою копию |
| S2 | CBM подключается к проекту в Claude Code и OpenCode; в Codex - один глобальный сервер со списком из восьми инструментов | глобальная регистрация загружает около 14 схем инструментов в каждую сессию Claude, включая папки без кода; `enabled_tools` Codex держит схему малой | глобальная регистрация везде |
| S3 | `codebase-memory-mcp install` и `update` для обновления не используются; после любого стороннего установщика выполняются `normalize` (Claude) и `manage.py install` (Codex) | установщик находит всех агентов и дописывает им hooks, глобальные MCP и блок в `AGENTS.md` | доверять установщику разработчика |
| S4 | Codex использует нативные `tool_output_token_limit`, `project_doc_max_bytes` и компактизацию вместо context-mode | нативные механизмы закрывают роль без второго фильтра того же вывода | context-mode в Codex |
| S5 | Headroom по умолчанию выключен и для Codex не применяется | меняет маршрут к провайдеру и авторизацию; выключен из-за нестабильной работы; при выключении `ANTHROPIC_BASE_URL` явно задаётся официальным адресом | постоянный прокси для всех агентов |
| S6 | RTK экспериментален и оценивается только A/B-прогоном на одинаковых задачах; Codex вызывает его через адаптер, добавляющий `permissionDecision: allow` | `rtk gain` измеряет сокращение вывода, а не стоимость законченной задачи | считать `rtk gain` экономией |
| S7 | TokenEconomizer работает с общими `shadow=true` и `toolprune=propose`; каждый агент переключает только свой плагин | сначала наблюдение; общий файл влияет на всех агентов | включать механизмы без замера; выключать через общий файл |
| S8 | У правил Caveman и Ponytail один источник на агента: плагин (Claude Code, OpenCode) или глобальный `AGENTS.md` (Codex) | плагин и копия в файле инструкций внедряют одни правила дважды на каждом ходе | оба сразу |
| S9 | Два режима: dev (полный стек без Headroom) и doc (без Caveman, context-mode, Ponytail) | инструменты, меняющие ответ, портят официальные документы; инструменты трафика - нет | один режим на всё |
| S10 | Права Codex повторяют Claude Code: чтение всей файловой системы, кроме путей, запрещённых для чтения Claude; запись в рабочей папке; `auto_review` для остального; профиль не запрещает `":root"`; `doctor` выполняет `codex sandbox -- /bin/true` | одна политика для всех агентов человека; запрет `":root"` скрывает бинарник Codex от его же песочницы bwrap и ломает любую команду оболочки | более строгий профиль только для Codex; `-s workspace-write` в командах воркеров (отменяет профиль и открывает чтение всего) |
| S11 | Бюджет задержки hook - около 100 мс; замер после каждого обновления плагина | hooks выполняются при каждом вызове инструмента; штатная диагностика может показывать OK, пока hook работает секунды | доверять штатной диагностике |
| S12 | Публичная часть в git, особенности машины - в исключённом из git `local/`; локальные правила агента дописываются к сгенерированным глобальным | один репозиторий служит автору и любому, кому его передали, не раскрывая пути, хосты и расположение секретов | частная копия для каждой машины |
| S13 | Каждый агент владеет своим каталогом конфигурации; остальные только читают его | независимые переключатели; изменение одного агента не ломает другого | один скрипт, управляющий всеми агентами |
