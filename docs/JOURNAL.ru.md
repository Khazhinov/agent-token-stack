## 2026-11-03 - сбой песочницы Codex, равенство прав, этот репозиторий

- Профиль Codex запрещал `":root"`. Codex запускает собственный бинарник внутри bwrap, поэтому любая
  команда оболочки падала с `bwrap: execvp .../codex`; агенты, запущенные без явного `-s`,
  останавливались, ничего не сделав. Обход через `-s workspace-write` скрывал ошибку, но отменял
  профиль и открывал чтение всех файлов.
- Исправление: профиль Codex повторяет Claude Code - читается всё, кроме путей, запрещённых для чтения
  Claude; запись в рабочей папке; `auto_review` для остального. `doctor` выполняет
  `codex sandbox -- /bin/true`.
- Найдено расхождение соглашений о путях в Claude Code: в правилах `Read(...)` одиночный ведущий `/`
  отсчитывается от источника настроек (`~/.claude` для пользовательских), в `sandbox.filesystem.denyRead`
  он абсолютный. Установщик Codex учитывает оба соглашения.
- Стек перенесён в этот репозиторий: одно публичное описание с примерами и обоснованием для каждого
  агента, особенности машины - в исключённом из git `local/`.

- Каждый агент перенёс сюда свою часть стека: скилл `stack` Claude Code связан с `agents/claude-code`,
  состояние переключателя хранится рядом и исключено из git; Codex устанавливается из `agents/codex`;

  содержат только настройки, не относящиеся к стеку.
- В глобальные правила каждого агента добавлено краткое уведомление: стек существует, где он описан,
  какой командой переключается компонент; агент только предлагает переключение и сам не переключает.
- OpenCode отсчитывает относительные пути `instructions` от рабочего каталога; в глобальном файле
  указывается абсолютный путь.
- `codex sandbox -- /bin/true` падает при запуске изнутри сессии Codex; проверка выполняется из
  обычного терминала.
- После переноса каждый новый исполнитель Codex останавливался на экране «Hooks need review»: Codex
  хранит доверие к hook по файлу и позиции hook и сравнивает хэш его команды, а команда содержала путь
  репозитория. Теперь команда идёт через ссылку скилла, которая при переносе указывает на новое место;
  доверенный хэш остаётся действительным.

## 2026-11-09 - сеть Codex для локальных сокетов

- Сессия Codex не получала доступа к herdr-core: `hc` в песочнице получал `Operation not permitted` на
  Unix-сокете ядра, затем пытался запустить второе ядро и завершался ошибкой (шина systemd, файловая
  система только для чтения). Codex в роли владельца GSD или исполнителя herdr не мог запускать агентов
  и следить за ними.
- Проверки `codex sandbox` (0.167): разрешение одного сокета (`network.unix_sockets`) не помогает ни
  с сетевым прокси, ни без него; помогает `network.enabled = true`.
- Профиль `workspace-only` теперь включает сеть. Это совпадает с Claude Code, где Bash работает с
  сетью; запреты чтения секретов и запись только в рабочую папку сохраняются.

## 2026-11-09 - Codex без общего демона, запись в кэши оркестрации

- Обычный `codex` (0.167) подключается к общему демону app-server. Демон выполняет команды оболочки с
  окружением терминала, из которого был запущен: владелец GSD видел `HC_TERMINAL_ID` другого проекта, а
  `codex sandbox` внутри такой сессии завершался ошибкой (вложенная песочница).
- `features.daemon_auto_start = false` оставляет обычный `codex` в собственном процессе. Пока жив старый
  демон, Codex один раз спрашивает, работать ли без него; после остановки демона вопрос не появляется.
- Профиль `workspace-only` разрешал запись только в рабочей папке, поэтому журналы квот и блокировки в
  `~/.cache/herdr-orch` и кэш kit завершались ошибкой `Read-only file system`. Оба кэша теперь доступны
  для записи; правило `write` для отсутствующего пути `codex sandbox` принимает.

- Новая установка Claude Code по репозиторию (без установщика CBM производителя) после `/stack mode dev`

- Репозиторий теперь содержит `cbm-session-reminder.sh`, который молчит вне проектов с подключённым CBM.
  `toggle.py` регистрирует hook только при наличии его скрипта и сообщает о пропущенных.
