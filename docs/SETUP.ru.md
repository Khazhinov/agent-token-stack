# Настройка

[English](SETUP.md) | Русский

Порядок работы агента, настраивающего стек на машине. Подходит для Claude Code, Codex CLI, OpenCode
и любого их сочетания. Перед установкой сверять каждую команду с актуальным README инструмента:
наборы поддерживаемых сред меняются от версии к версии.

## 1. Обнаружить окружение и сохранить исходное состояние

1. Определить ОС, WSL или контейнер, архитектуру, домашний каталог, установленные `codex`, `claude`,
   `opencode`, `rtk`, `codebase-memory-mcp`, активный `CODEX_HOME` и настройки Claude. Проверить,
   как агенты запускаются на деле (мультиплексор терминалов или настольное приложение может
   переопределить профиль или окружение); не делать вывод по названию каталога.
2. Снять версии, MCP-серверы и плагины, активные hooks, пути бинарников, текущие лимиты и права.
   Найти проекты с существующими индексами CBM; не индексировать их все заранее.
3. Сохранить резервные копии изменяемых файлов. Не перезаписывать модель, авторизацию, другие
   MCP-серверы, инструкции человека и секреты. Не выводить секреты.
4. Если на машине уже есть управляющие скрипты или skills, изучить их и использовать как источник
   конфигурации: менять исходный файл и применять его установщиком, а не править сгенерированную копию
   в домашнем каталоге.
5. Записать найденное в `local/README.md` (профиль машины) и начать `local/JOURNAL.md`.

## 2. Общий слой

1. Установить одну совместимую версию CBM из
   [официальных релизов](https://github.com/DeusData/codebase-memory-mcp/releases) и проверить SHA-256
   бинарника. Для закреплённой версии это делает `manage.py install`. Не запускать
   `codebase-memory-mcp install` поверх готовой конфигурации нескольких агентов.
2. Подключить CBM ровно один раз в каждом агенте ([STACK.ru.md](STACK.ru.md), раздел 3). Индексировать
   проект, когда в нём начинается работа.
3. RTK необязателен: устанавливать вместе с задачей, на которой его можно сравнить с режимом без RTK.
   Бинарник один на машину.
4. TokenEconomizer устанавливать, только если поддерживаются текущие версии агентов. Начинать с общего
   `shadow=true` и `toolprune=propose`, без автоматического отключения инструментов.

## 3. Каждый агент

**Codex:** запустить `agents/codex/install.sh`. Он связывает `~/.codex/AGENTS.md` и скилл `token-stack`,
объединяет управляемые блоки с `~/.codex/config.toml` (модель, доверие и прочие настройки сохраняются),
добавляет hook RTK в `~/.codex/hooks.json` и выполняет `doctor`. Локальные правила машины - в
`local/codex/AGENTS.md`, `install` дописывает их к глобальному файлу. Подробности:
[agents/codex/README.ru.md](../agents/codex/README.ru.md).

**Claude Code:** связать `agents/claude-code/skills/stack` с `~/.claude/skills/stack`, добавить правила
из [agents/claude-code/RULES.md](../agents/claude-code/RULES.md) в `~/.claude/CLAUDE.md` (или
импортировать через `@<путь>`), установить выбранные плагины и выполнить `/stack normalize`, затем
`/stack`. Подробности: [agents/claude-code/README.ru.md](../agents/claude-code/README.ru.md).

**OpenCode:** по [agents/opencode/README.ru.md](../agents/opencode/README.ru.md).

**Несколько агентов:** общие бинарники и кэш CBM обновляет один агент за раз; настройки, hooks и
плагины переключаются у каждого агента отдельно. Проверка независимости: записать состояние каждого
агента и общего файла TokenEconomizer, переключить один компонент у одного агента, убедиться, что
у остальных ничего не изменилось, вернуть исходное.

## 4. Среда запуска

Если агенты обычно запускаются из мультиплексора или настольного приложения, записать это в
**глобальные** инструкции каждого агента через `local/<agent>/`, чтобы правило действовало и в пустой
папке: где работает процесс агента, где интерфейс, и что запускающая программа может переопределять
параметры.

## 5. Проверки

1. Синтаксис изменённых конфигураций, один экземпляр каждого MCP-сервера, состояние плагинов,
   переключатели каждого агента, нативные лимиты, неизменность политики прав.
2. `manage.py doctor` (включает `codex sandbox -- /bin/true`), `/stack`, `opencode debug config`.
3. Один небольшой запрос через каждого установленного агента.
4. Задержка hooks: каждый не дольше примерно 100 мс ([TROUBLESHOOTING.ru.md](TROUBLESHOOTING.ru.md)).
5. Если интеграция ломает агента, выключить только её локальный компонент, восстановить файл из
   резервной копии и повторить проверку. Общие бинарники и индексы при локальном откате не удалять.

## 6. Отчёт человеку

Найденные среды и версии; изменённые файлы и резервные копии; общие и локальные компоненты; точные
команды `status`, `on`, `off` для каждого агента; результаты проверок; что осталось экспериментальным.
То же записать в `local/JOURNAL.md`.

## 7. Замер экономии

Взять 10-15 типовых задач из репозиториев человека. Сравнивать одинаковые коммиты, модели и effort,
минимум по три повтора: базовый стек, без RTK, затем по одному механизму TokenEconomizer. Измерять
полные и кешированные входные и выходные токены, число ходов и компактизаций, время, результат тестов и
долю успешных первых попыток. Стоимость подписки и недоступные метрики отмечать отдельно, без
выдуманной цены. После каждого прогона возвращать базовую конфигурацию; auto review не отключать.
